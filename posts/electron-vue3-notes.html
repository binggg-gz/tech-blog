Electron + Vue 3 + TypeScript 桌面应用开发踩坑记录

基于 MediaTrace 项目整理 Electron 33 + Vue3 + Playwright 的工程实践:渲染进程隔离、自动更新、Playwright 下载与打包的常见问题。

MediaTrace 是我在维护的一个桌面应用,技术栈是 Electron 33 + Vue 3 + TypeScript + Playwright。这篇文章把开发过程中真正卡住我的几个问题整理出来,每个都附了解决方案,属于"早知道能省半天"的那种笔记。

1. Playwright 的浏览器下载

第一次装好 Playwright 跑脚本报 browserType.launch: Executable doesn't exist。原因是 npm 装 Playwright 时不会自动下载浏览器二进制,需要手动执行:

npx playwright install chromium

注意国内网络直接 install 很容易超时,可以加镜像:

PLAYWRIGHT_DOWNLOAD_HOST=https://cdn.npmmirror.com/binaries/playwright
npx playwright install chromium

打包成 Electron 应用时,Playwright 的浏览器不会打进安装包,要么随包分发(体积 +150MB 左右),要么首次启动时静默下载。

2. 渲染进程里用不了 Node API

Vue 组件里 require('fs') 直接白屏——Electron 默认给渲染进程关了 Node 集成。正确做法是分层:

  • 渲染进程(Vue):只碰 UI,通过 window.api 调预暴露的方法
  • 预加载脚本(preload):用 contextBridge.exposeInMainWorld 白名单式暴露接口
  • 主进程:所有文件、网络、系统调用在这里执行
// preload.ts
import { contextBridge } from "electron";

contextBridge.exposeInMainWorld("api", {
  readFile: (path: string) => ipcRenderer.invoke("file:read", path),
});

配套的 webPreferences 一定要显式收紧:

new BrowserWindow({
  webPreferences: {
    contextIsolation: true,
    nodeIntegration: false,
    sandbox: true,
    preload: path.join(__dirname, "preload.js"),
  },
});

3. TypeScript 的类型声明

window.api 在 Vue 里是 any 的话,TS 就白装了。建一个 types/global.d.ts:

interface ElectronApi {
  readFile: (path: string) => Promise<string>;
}

declare global {
  interface Window {
    api: ElectronApi;
  }
}

export {};

注意文件里必须有 export {},否则会被当成脚本而不是模块,全局声明不生效。

4. 自动更新

Electron 没有内置更新器,常用组合是 electron-updater + 一个静态文件服务器(或 GitHub Releases):

import { autoUpdater } from "electron-updater";

autoUpdater.checkForUpdatesAndNotify();
autoUpdater.on("update-downloaded", () => {
  autoUpdater.quitAndInstall();
});

坑在于:开发环境不会触发更新,autoUpdater 只在打包后的应用里工作。测试更新流程时,要么打一个低版本号的包装上,要么用 dev-app-update.yml 指向本地目录模拟。

5. Vue 3 的 keep-alive 与路由

Vue Router 4 里用 keep-alive 缓存列表页,返回时不再重新请求数据。但缓存会导致"数据不刷新"的 bug——退出详情页回来列表不动。解法是给列表页注册 onActivated 钩子,按需刷新:

import { onActivated } from "vue";

onActivated(() => {
  if (needsRefresh.value) loadList();
});

打包体积优化

默认 electron-builder 产物 80MB 起步。几个有效的瘦身手段:

手段效果
用 Vite 构建渲染进程,替代 webpack产物体积明显下降,构建更快
只打单平台单架构(如 mac arm64)安装包减半
剔除 asar 里的 source map 和 locales 多余语言再省 10-20MB

小结

Electron + Vue 3 的开发体验已经相当成熟,真正的坑都集中在进程边界和分发环节:进程隔离要早做,别等报错了再拆;更新和下载逻辑要在打包环境下验证,开发环境看不出来。
